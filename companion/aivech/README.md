# Companion aivech — снимок работающего сервиса

Этот каталог сохраняет исходники единственного Telegram polling-процесса, который сейчас работает рядом с BB. Он обслуживает команды `/projects`, `/tasks`, `/status` и отдельную доставку SMS. Плагин BB пишет для него projection-файл маршрутов. Это персональная конфигурация, не универсальный установщик.

`npm ci && npm test` проверяет сборку и обработчики без подключения к настоящему боту. `npm start` запускает реальный сервис: не запускать вторую копию рядом с launchd-процессом.

Рабочий каталог на Mac mini: `/Users/vechkasov/toolkit/service-bots/aivech`. Сервис использует закрытый `../private/aivech.json`, соседнюю SMS SQLite-базу и файлы очереди/состояния. Эти файлы намеренно не входят в репозиторий. Пример формы конфигурации: `{"token":"<BOT_TOKEN>","chat_id":259034221,"enabled":true}`. Пути и проверка bot/owner ID фиксированы в исходниках.

Копия здесь не заменяет автоматически запущенный сервис. Изменения сначала проверяются, затем синхронизируются в рабочий каталог с сохранением private-файлов и перезапуском существующего процесса. Будущий транспорт должен владеть единственным получателем updates; SMS останется самостоятельным модулем. См. ../../docs/architecture.md.

## Чат-транспорт 0.2

`src/chat.ts` сохраняет owner-only сообщения и callbacks в `private/bb-chat-inbox` (атомарный файл и fsync). Флаг `private/telegram-chat.json` включает делегирование команд плагину; при перезапуске BB входящие продолжают сохраняться. `/tasks` обслуживается companion по projection, включая дополнительные темы через chatBindings. Все остальные команды/текст/голос обрабатываются BB-плагином. Новый poller в плагине не запускается.

При отключённом chatEnabled плагин выключает флаг; во время временной недоступности BB он сохраняется для надёжного приёма. Core-disable/uninstall плагина требует отдельно выключить флаг, если нужно вернуть только сервисные команды. Не удалять spool с необработанными сообщениями при обновлении.
