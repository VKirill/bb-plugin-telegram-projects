# BB в Telegram: исследование и решение

Проверено 12 сентября 2026. Это сравнение документированных возможностей, а не нагрузочный тест или аудит безопасности чужого кода. Конкуренты не устанавливались. Наш развёрнутый релиз 0.1.0 пока синхронизирует проекты и уведомления Tasks.

## Вывод

Развивать собственный плагин как транспорт к обычным сессиям BB. Источником проектов, окружений, моделей, вопросов и истории остаётся BB. У Telegram — навигация, приём сообщений и отображение результата. Такой подход соответствует запросу на одни настройки и позволяет продолжить мобильный разговор в BB.

Не нужен отдельный Telegram-агент с собственной памятью, планировщиком и параллельной системой задач. Для реализации стоит изучить надёжную доставку Hanoon, навигацию Takopi/Hermes и rich-рендеринг OpenClaw.

## Аналоги

| Решение | Что подтверждено документацией | Применение у нас |
|---|---|---|
| **Hanoon / Telegram Agent** | Прямой плагин BB: личный Telegram-вход, голос, вопросы и разрешения, управление потоками, durable inbox/outbox, собственный контроллер и память | Самый близкий технический референс; взять принципы доставки и привязки взаимодействий |
| **Needs You** | Плагин BB из текущего каталога: уведомления о вопросах, ошибках и завершениях; ответить/одобрить с телефона нельзя | Референс подключения и настройки уведомлений; не заменяет двусторонний интерфейс |
| **Takopi** | Telegram-мост к Codex, Claude Code, OpenCode и Pi; проекты/worktrees, прогресс, голос, очереди сессий | Компактная навигация и продолжение работы в исходном агенте |
| **cc-connect** | Несколько агентов и мессенджеров, команды сессий, моделей и провайдеров, голос, разрешения | Удобный командный словарь; области действия настроек нужно адаптировать к BB |
| **OpenClaw** | Telegram-транспорт с темами, командами, кнопками, потоковым выводом и native Rich Messages | Форматирование и взаимодействия; не требуется переносить его собственный runtime |
| **Hermes Agent** | Темы как отдельные сессии, локальный сброс темы, меню моделей, восстановление сессий, транскрибация | Изоляция разговоров и меню без множества служебных сообщений |
| **Claude Code Channels** | Официальный канал в работающую сессию Claude Code, pairing и relay разрешений | Пример адресных разрешений; наш интерфейс должен работать с разными провайдерами BB |

### Прямые аналоги BB

[Hanoon](https://github.com/amrtawfik160/hanoon) изучен по README на commit `25550a9b2975abf3a72d3549436e9ead01a71da9`. Его подход шире нашего: собственная долговременная память, контроллер, мониторинг и pipeline. README описывает наблюдение за завершением, ошибкой и блокировкой всех верхнеуровневых потоков. У нас область доставки должна быть уже: Tasks и явно привязанные разговоры. Для Hanoon заявлена MIT-лицензия; перед заимствованием реализации потребуется проверить конкретные файлы и сохранить атрибуцию. Сейчас код не заимствован.

По `bb plugin search telegram --json` в подключённых каталогах найден [Needs You](https://github.com/notpritam/bb-plugin-inbox). Карточка прямо указывает: Telegram служит для уведомлений, ответы и approvals выполняются внутри BB. Hanoon в этом результате поиска не появился; это не означает отсутствия других проектов или будущей публикации.

### Транспорт и меню

[Takopi](https://github.com/banteg/takopi) полезен моделью тонкого моста: Telegram управляет существующими coding agents, поддерживает project/worktree routing, прогресс и возвращение к терминальной сессии. Это ближе к нашему назначению, чем новая автономная платформа.

[Команды cc-connect](https://github.com/chenhg5/cc-connect/blob/main/docs/usage.md) покрывают `/new`, `/list`, `/switch`, `/current`, `/history`, `/provider`, `/model`, `/stop`. В документации переключение модели может затрагивать общий экземпляр агента проекта. У нас изменение должно иметь явно показанную область: текущая сессия или настройки новых сессий. Нельзя неожиданно менять модель соседнего рабочего чата.

[Telegram в Hermes](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/messaging/telegram.md) предлагает отдельные сессии по теме, `/new` для текущей темы, восстановление сессии и выбор модели через редактируемое меню. Полезная практика — сохранять предыдущую сессию при начале новой, а не стирать историю. Голос автоматически транскрибируется.

### Ответы, вопросы и оформление

[OpenClaw: rich messages](https://docs.openclaw.ai/channels/telegram/rich-messages) документирует отдельное включение native Rich Messages, обычный HTML как совместимый режим и зависимость отображения от клиента. [Темы и сессии](https://docs.openclaw.ai/channels/telegram/threads-and-sessions) показывают, что привязка темы требует отдельного состояния маршрута. Для нашего плагина это аргумент за отдельные модули renderer и routing.

[Claude Code Channels](https://code.claude.com/docs/en/channels-reference) связывают запрос разрешения с идентификатором запроса. Ответ из второго интерфейса после решения в терминале уже не должен выполнять действие. В BB используем его собственные PendingInteraction, а не протокол Claude.

[Telegram Bot API](https://core.telegram.org/bots/api#sendrichmessage) предоставляет native `sendRichMessage` и `sendRichMessageDraft`, в том числе структурированные блоки. Текущие наши карточки через `sendMessage` с HTML — другой формат. Следующий renderer должен уметь сохраняемый итоговый rich-ответ, обновляемый прогресс и совместимый текстовый режим. Таблицы, раскрываемые подробности и вложения следует проверять на реальном телефоне.

## Что не установлено исследованием

Мы не проверяли чужие сервисы на своём боте, не измеряли их стабильность, стоимость или задержки и не проводили полный code audit. Заявленные возможности не гарантируют совместимость с нашей версией BB. Voice API найден в локальном SDK; полный путь Telegram OGG → BB → сессия ещё не проверен. Точное поведение разных провайдеров при смене модели и интерактивных запросах нужно проверить в прототипе.

## Настройки BotFather

Для личных тем уже включён Threaded Mode. Bot Management Mode относится к управлению другими ботами. Общение агентов внутри BB не требует Bot-to-Bot Communication: агенты могут работать через BB, а общий бот показывать результаты. Если позже будут отдельные Telegram-боты, их взаимодействие оформляется отдельной функцией с адресными сообщениями и ограничением циклов. Автоматические ответы каждого бота на каждое сообщение не подходят.
