# Telegram Projects

Самостоятельный плагин BB для личного @aivech_bot. Работает рядом с Projects & Sections через публичные SDK проектов; изменения исходного плагина не нужны. Сервер и сервисный бот сейчас работают на Mac mini.

## Поведение

- Один проект BB → одна тема Telegram, независимо от числа окружений/машин.
- Создание и переименование проекта синхронизируются автоматически. Сверка каждые 15 секунд плюс сигнал изменения проекта; запросы Tasks/Telegram могут увеличить задержку.
- Удаление проекта удаляет тему **со всей историей** после отсутствия проекта минимум 30 секунд в успешных снимках. Настройка deleteTopics может отключить это поведение. Удаление плагина/его выключение ничего в Telegram не удаляет.
- Дополнительные темы «Навигация» и «SMS» не связаны с удалением проектов.
- Подпроекты Tasks направляются через linkedBbProjectId. В карточке видно название подпроекта и ключ задачи. Отдельные папки Projects & Sections пока не создают отдельные темы.
- Уведомления: новая задача, смена статуса (включая запуск, проверку, завершение, отмену), появление работающих исполнителей при неизменном статусе, изменение срока, переход прикреплённого в Tasks исполнителя в error.
- Рабочие события — отдельные короткие карточки с кнопкой прямого перехода к задаче. Звук только для проверки и ошибок. Завершение определяется статусом Tasks; остановка worker не считается завершением задачи.
- Нет чтения сообщений/таймлайнов обычных чатов, нет пересылки ответов агентов, комментариев Tasks или вложений. Ошибки worker содержат только факт ошибки, не приватный текст.
- Первое подключение создаёт тихий снимок существующих задач. Новые подпроекты и задачи после начала наблюдения отслеживаются автоматически. Tasks читаются через публичный CLI с пагинацией; приватные базы других плагинов не открываются.

## Установка и эксплуатация

`npm install`, `npm run check`, `npm test`, `bb plugin build`, `bb plugin install . --yes`.
Плагин устанавливается с настройкой enabled=false. После проверки сервера, bot ID и owner ID: `bb plugin config telegram-projects set enabled true`.

`bb telegram-projects status --json` — темы, очередь, последняя синхронизация и категория ошибки.
`bb telegram-projects sync --json` — сверка сейчас.
`bb telegram-projects test <project-id>` — явно отмеченная тестовая карточка.
`bb telegram-projects bind <project-id|sms|navigation> <topic-id>` — восстановление привязки к существующей теме. Сначала проверить, что это нужная тема: команда переименует её согласно сохранённой привязке.

Страница BB: `/plugins/telegram-projects/telegram-projects`.
Настройки: enabled, configFile, projectionFile, cliPath, appUrl, deleteTopics, notifyTasks, notifyWorkerErrors, soundOnReview.

## Секреты и границы

Это персональная интеграция: bot ID 8461763634 и owner ID 259034221 фиксированы. Поддержка произвольных ботов потребует отдельного расширения конфигурации. configFile — закрытый JSON **на сервере BB**, с token, chat_id и enabled. Значения токена не логируются и не передаются браузеру. Все исходящие запросы фиксируют адресата владельцем. Settings не хранят сам токен.

Плагин не вызывает getUpdates и не устанавливает webhook: существующий launchd-сервис aivech остаётся единственным обработчиком входящих сообщений. Файл projectionFile — атомарно обновляемый снимок маршрутов и активных задач, mode 0600, для команд /projects, /tasks, /status и SMS-маршрута. Снимок исходников сервисного бота сохранён в [companion/aivech](companion/aivech/README.md); рабочий процесс отдельно развёрнут в toolkit/service-bots/aivech.

## Восстановление и ограничения

Состояние — собственная SQLite через bb.storage, очередь сохраняется при перезапуске. Telegram 429 учитывает retry_after. При неопределённом исходе создания темы повторное создание блокируется до ручной привязки: Telegram Bot API не предоставляет ключ идемпотентности createForumTopic. Для сообщений действует повторная доставка: при обрыве между успешной отправкой и записью квитанции возможен один дубль. Старые квитанции очищаются через 30 дней.

Сверка замечает состояния на момент опроса. Короткие промежуточные смены статуса между опросами могут не попасть в Telegram. Это обзор состояния, не полный журнал событий Tasks. Перенос назначения linkedBbProjectId применяется к новым событиям; уже поставленные в очередь события остаются привязанными к исходному проекту.

Не очищать plugin storage при обычном обновлении: это потеряет привязки тем. После ручного удаления темы в Telegram нужно восстановить/перепривязать её; плагин не угадывает тему по похожему названию. При ошибке источника задачи не удаляются и Telegram-темы не пересоздаются.
